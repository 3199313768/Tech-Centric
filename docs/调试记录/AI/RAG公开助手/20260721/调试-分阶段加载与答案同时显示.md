# 调试：分阶段加载与答案同时显示

## 1. 根因

首个 SSE `delta` 同时写入答案并把加载阶段设为 `generating`，导致答案消息与分阶段加载条在同一次渲染中并存；消息列表位于加载条之前，因此答案把加载条向下推。

## 2. 影响范围

- 页面：全站浮动 RAG 公开助手。
- 路径：用户提问后接收流式回答。
- 严重程度：P1，本迭代修复。
- 生产数据：不影响，仅影响展示顺序与等待体验。

## 3. 临时规避方案

无。用户只能等待回答完成后加载条消失。

## 4. 可能链路

`submitMessage` 创建空助手消息 → SSE `delta` 到达 → `applyRagSseEvent` 追加答案 → `loadingStage` 变为 `generating` → 消息和加载条同时渲染。

## 5. 复现步骤

1. 打开浮动助手。
2. 提交任意可正常流式回答的问题。
3. 等待首段答案出现。
4. 观察答案出现在“正在组织回答”上方，并把阶段条推到下方。

## 6. 最可疑代码

- `src/components/rag/chat/ChatPanel.tsx`：SSE 回调中把 `delta` 映射为 `generating`。
- `src/lib/rag/chatState.ts`：`delta` 会立即把文本写入当前助手消息。

## 7. 快速定位方法

对照 SSE 事件顺序检查 UI 状态：`meta` 表示检索完成并准备生成，`delta` 表示答案内容已经开始展示。加载阶段应在 `meta` 进入组织回答，在 `delta` 隐藏。

## 8. 如何加日志

开发环境可在 SSE 回调中临时记录 `event.type`、当前 `loadingStage` 和最后一条消息内容长度；修复验证后不保留日志，避免公开问答内容进入浏览器日志。

## 9. 彻底修复

新增纯函数统一事件到加载阶段的映射：`meta → generating`，`delta/done/error → null`。`ChatPanel` 使用函数式状态更新，避免闭包读取旧阶段；首个事件同时清除阶段定时器，防止后续定时器覆盖新状态。

## 10. 回归风险

- 首个 `meta` 到达前，“正在理解问题”和“正在检索资料”的定时推进。
- SSE 缺少 `meta` 时，首个 `delta` 仍需隐藏加载条。
- `done`、`error` 和组件卸载时不得遗留加载状态或定时器。

## 11. 验证方法

- 单元测试验证 `meta → generating`、`delta/done/error → null`。
- 执行 `pnpm test:unit src/lib/rag/chatUi.test.ts`。
- 手动提问，确认首段答案出现时加载条同时消失，答案不会把加载条向下推。

## 12. 如何避免再次出现

将请求生命周期状态集中在纯函数中测试，新增 SSE 事件或调整流式 UI 时，同时验证“阶段提示”和“答案内容”是否允许并存。
