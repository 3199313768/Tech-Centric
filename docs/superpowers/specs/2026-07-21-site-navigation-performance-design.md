# 站内导航性能优化设计

## 目标

让 `(site)` 路由切换后立即展示稳定的页面骨架，并减少 `/projects`、`/skills`、`/resources` 首次进入时加载的非首屏管理 UI。

## 范围

本次包含：

1. 为 `src/app/(site)` 增加路由级 `loading.tsx`。
2. 项目页延迟加载详情、编辑和删除弹窗。
3. 技能页延迟加载新增编辑弹窗及删除确认 UI。
4. 资源页仅在需要时挂载表单、发现、确认等动态弹层。

本次不修改 Supabase 查询、缓存策略、权限模型、页面视觉设计或业务操作结果。

## 路由骨架

`src/app/(site)/loading.tsx` 使用现有 `SitePageFallback`，作为整个站点路由组的即时导航反馈。骨架保持与子页面接近的最小高度，避免导航、页脚和内容区域发生明显布局跳动。

页面内部已有的 `Suspense` 保留，用于服务端数据和客户端模块的局部加载；路由级骨架负责目标路由尚未返回可展示 RSC 内容之前的空档。

## 客户端组件拆分

### 项目页

将内联 `ProjectModal` 从 `AllProjects.tsx` 移至独立文件。详情弹窗通过 `dynamic()` 导入，并且只在 `selectedProject` 存在时挂载。`AddAllProjectModal` 只在新增或编辑状态打开时挂载。

列表、筛选、项目卡片和详情页跳转保留在首屏模块中。

### 技能页

`AddSkillModal` 只在打开状态挂载。删除确认条从技能卡片的常驻依赖中移出为动态组件，只在用户请求删除时加载。

技能列表、平台和标签筛选、仓库跳转继续保留在首屏模块中。

### 资源页

保留搜索、分类、置顶、访问和复制等浏览交互。已有动态弹层改为条件挂载：

- `ResourceFormModal` 仅在 `showForm` 时挂载。
- `ResourceDiscoveryModal` 仅在 `showDiscoveryModal` 时挂载。
- `ResourceConfirmModal` 仅在 `confirmConfig.isOpen` 时挂载。

这样关闭状态不会触发动态模块加载。批量管理条属于轻量首屏交互，暂不再抽象，避免为单一区块增加额外状态边界。

## 数据流与错误处理

动态组件继续接收现有状态和回调，不改变 Server Action 调用方式。模块下载期间使用小型加载占位；下载或操作失败仍沿用现有 Toast 和错误处理。

关闭弹窗时卸载对应模块，下一次打开由浏览器模块缓存快速恢复。权限校验继续由现有 Server Action 执行。

## 测试与验证

- 静态策略测试确认 `(site)/loading.tsx` 存在并使用 `SitePageFallback`。
- 测试动态挂载判定：关闭状态不挂载，打开状态挂载。
- 项目、技能、资源现有浏览交互保持不变。
- 执行聚焦测试、相关文件 ESLint、`pnpm typecheck`、`pnpm build` 和 `git diff --check`。
- 对比开发环境下三个页面首次请求及热请求时间；开发环境结果只用于相对比较，不作为生产指标。

## 成功标准

- 点击任意 `(site)` 导航后立即出现路由骨架。
- 三个页面关闭状态下不挂载任何新增、编辑、详情、删除确认或发现弹层。
- 打开管理操作时对应动态模块正常加载，新增、编辑和删除行为保持一致。
- 首屏列表、筛选、导航和资源访问行为无回归。
