# RAG 公开助手交互优化设计

## 目标

增强公开 RAG 助手的等待反馈、无资料后的行动引导，以及长回答的阅读操作，同时保持现有检索、生成和 SSE 协议不变。

## 范围

本次包含三项功能：

1. 请求期间分阶段显示“正在理解问题 → 正在检索资料 → 正在组织回答”。
2. 无资料回答提供“查看项目”“浏览知识库”“联系园主”三个出口。
3. 完整回答支持复制；超过约 600 字的回答额外支持折叠、展开和回到顶部。

不修改检索算法、生成模型、索引流程、联系表单内容或服务端 SSE 协议。

## 交互设计

### 分阶段加载

使用前端请求生命周期驱动加载阶段：

- 用户提交有效问题后立即进入“正在理解问题”。
- 短暂延迟后进入“正在检索资料”。
- 收到第一段回答内容时进入“正在组织回答”。
- 请求完成、失败或取消后隐藏阶段提示并清理定时器。

阶段提示由独立组件渲染，当前阶段具有明确视觉状态，并通过 `aria-live="polite"` 向辅助技术播报。阶段属于用户体验提示，不作为服务端真实性能埋点。

### 无资料出口

当完整普通回答的 `evidenceMode` 为 `insufficient`，或回答完成但没有任何来源时，回答下方显示三个操作：

- “查看项目”跳转至 `/projects`。
- “浏览知识库”跳转至 `/knowledge`。
- “联系园主”复用现有 `contact:start` 操作，进入联系流程。

安全拒答和请求错误不展示这组出口，避免把安全响应误判为资料不足。

### 长回答操作

完整且无错误的普通 AI 回答显示“复制回答”。复制成功后复用助手现有轻提示反馈。

回答内容超过 600 个字符时：

- 默认完整展示。
- 用户可切换“折叠回答”和“展开回答”。
- 折叠状态使用约 6 行的视觉截断，不修改原始回答内容。
- 提供“回到回答顶部”，将当前回答气泡平滑滚动到可视区域顶部。

短回答只显示复制操作，不显示折叠和回到顶部，减少界面噪声。

## 组件边界

- `LoadingStatus`：只负责阶段标签和当前阶段的可访问展示。
- `AnswerActions`：负责复制、折叠、展开、回到顶部，以及无资料出口。
- `MessageBubble`：组合回答正文、来源、反馈和回答操作；不承担请求阶段状态。
- `ChatPanel`：维护请求阶段、计时器和联系流程入口，并向消息操作传递回调。

加载阶段与回答操作使用小型纯函数判定，便于单元测试，避免继续扩大 `ChatPanel` 内的条件分支。

## 状态与数据流

1. `ChatPanel` 提交请求，设置加载阶段为 `understanding`。
2. 定时器将阶段推进为 `retrieving`。
3. SSE 首个 `delta` 到达时，将阶段设置为 `generating`。
4. SSE `done` 将 `evidenceMode`、来源和完整状态写入对应消息。
5. `MessageBubble` 根据消息状态渲染 `AnswerActions`。
6. “联系园主”通过现有动作回调进入联系模式，站内出口使用 Next.js `Link`。

## 错误与边界

- 请求提前失败或取消时清理阶段定时器，避免关闭面板后继续更新状态。
- 剪贴板 API 失败时沿用现有 `textarea` 降级复制方案。
- 流式未完成的回答不显示复制、折叠或无资料出口。
- 联系模式、系统消息和用户消息不显示回答操作。
- 同一消息的折叠状态保留在组件实例内，不写入会话存储。
- 回到顶部只滚动当前回答，不改变整个页面路由或历史。

## 测试与验收

采用测试驱动实现：

- 加载阶段按请求开始、延迟和首个 `delta` 正确推进，并在结束时清理。
- `insufficient` 且完整的回答显示三个正确出口；错误和安全拒答不显示。
- 完整回答可复制；超过 600 字时显示折叠和回到顶部。
- 长回答默认完整，折叠后使用 6 行截断，再次展开恢复完整内容。
- 短回答不显示折叠和回到顶部。
- 相关测试通过后运行 `pnpm lint`、`pnpm typecheck` 和 `pnpm build`。

## 成功标准

- 用户在等待回答期间始终能看到当前处理阶段。
- 站内资料不足时，用户可以一步进入项目、知识库或联系流程。
- 长回答无需默认牺牲内容完整性，同时可以复制、折叠和快速定位顶部。
- 现有问答、来源引用、反馈和联系流程行为保持不变。
